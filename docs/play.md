# 雨线营地 · Godot 合作生存样片

**在同一 Wi-Fi 上试玩**，房主在当前目录运行下面的命令，然后在电脑浏览器打开终端打印的营地链接。队友只需浏览器，房主也无需打开 Godot 编辑器。

```sh
npm run coop:lan
```

- **本机入口**　点击「进入林地」，WASD 行走，鼠标转向，E 互动，Q 切换当前目标，V 切换第一人称与第三人称，Esc 松开鼠标并打开营地菜单。角色随真实移动自动迈步、腾空和落地；深水中会划水，停下后漂浮踩水，不需要选择姿态。点「邀请队友」后，邀请地址会选中。网页可点「复制链接」，也可按 ⌘C 或 Ctrl+C。把地址发给同一网络的朋友，房主的服务需保持运行。[打开雨线营地](http://localhost:4184/coop/?room=pine)
- **一场合作**　从木棚出发，可分头去鹿鸣溪谷取木料、去北坡瞭望塔取防水布。任务栏显示方位、距离及自己携带的材料。木料和防水布放入拾取者背包，同类各占一格；可以丢下交给队友。修屋者带齐木料和防水布各 1 份，回木棚按 E 修屋，所有人都能看到屋顶补齐、营灯亮起。有人在线时房间时钟前进，65 秒后开始下雨，15 秒内逐渐加大。晚归仍能完成任务。
- **湖岸和星空**　从鹿鸣溪谷沿水面朝西边的小栈台走。新房间第一场雨约在第 119 秒结束，随后可以在栈台看落日。约第 150 秒，抬头从南至西南一带开始找银河。昼夜一轮约 7 分钟。
- **从鹿鸣湖到外海**　在海岸试玩里，从湖北岸的「海湾」木牌沿山径登崖，再沿「沙滩」木牌走下缓坡。游过白浪礁线可在东侧沙嘴登岛。同一个房间内可以步行、下水、飞行，队友也能留在木屋。[本机海岸试玩](http://localhost:4494/coop/?room=pine) · [海岸路线](coast.md)
- **野外图册**　按 **M** 开关地图。用滚轮或 **+ / −** 缩放，左键拖动。点击六处地标可传送，联机时可看见同房间队友。右键放置个人标记，刷新后仍会保留。[本机图册试玩](http://localhost:4794/coop/?room=pine) · [图册操作与复验](field-atlas.md)
- **营地声音**　点击「进入林地」后可听到脚步、石块、游泳和红船引擎声。走上木栈台、踩进浅水或进入林地时，脚步会随地面变化。附近队友也能听到这些动作。
- **飞船和潜水**　从出生点转身，沿小径往溪谷走约 6 米即可看到红色飞船。看向停稳的飞船按 E 上下机。空格上升，C 下降，WASD 飞行，鼠标转向，V 切换视角。可尝试停在湖面、宽石面或树冠上，承托不足时船体会滑落。下机后在陆地按空格跳跃，进入深水后用 WASD 游泳、C 下潜、空格上浮。
- **用石块**　木棚外的出生点和栈台入口附近都有手掌大小的石块。走近并低头，对准扁石片按 E 捡起，再拿到营地固定磨石旁，看到「F 磨利手里的扁石片」后按 F。空手对准磨石时，按 E 或 F 可查看最近可捡扁石片的方位。靠近帆布角或麻绳时，按 F 执行当前提示。持物时用左键投掷，按 G 放下。投石入湖会激起水花与涟漪，浅水里的石块还能捡回。
- **木桌与背包**　苹果、面包和水壶在木棚右侧桌上。E 拾取，F 可当场吃东西或向水壶喝水。木棚左侧地上有一只背包，先按 E 捡到的人自动背上，格数由 6 增到 12。Tab 打开物品栏，用模型小图辨认物品。同种东西只占一格并累加总数，基础/扩展背包可容纳 6/12 种物品。溪边按 F 采集的溪水，无论数量都归同一格；选中后可「喝一份」，满水时保留不浪费。靠近木桌可将食物或溪水「放桌上」，桌上的溪水有实际水壶，E 拾回合并，F 直接喝一份。
- **角色与服装**　开局穿着帽子、夹克和长裤。按 Tab 后切到「角色」，拖动全身模型可以转身查看装备。选中部位便可穿上包里的同部位衣物、脱下收进背包，或直接丢到脚边。走近地上的衣物可按 E 拾取。
- **营地藏獒**　藏獒会在木屋入口和屋前空地走动。看向它走近按 E 收养。主人可按 E 切换跟随和原地待命。点亮营灯后，它会回门廊趴一会儿。
- **鹿鸣湖动物**　沿溪谷到湖的东南岸找鳄鱼。看到扑咬预警时后退，受伤可以回修好的木屋恢复。老鹰会绕湖飞行，也会落在东岸栈台附近的松枝上。
- **来袭者与自由同伴**　首次在线 540 秒后会先有 30 秒预兆，准备食物、溪水和药草。B 打开营地住民与补给来源；看向附近的人按 E 查看。左键使用当前手持武器，不另选战斗姿态；徒手、圆石和木棍为钝击，长矛和磨利石片为锐器。1–4 切换已缴获的武器，5 装备盾牌后按住右键抵挡。钝器可击晕，锐器实际击中左右腿会分别减速。明确制服后亲自供给、治疗并建立信任，对方才可能自愿留下；自由同伴可以守家、自主取食取水、接受装备和自愿发展关系。完整流程、物资来源、人数上限与调参见[来袭者与自由同伴](wild-people.md)。
- **木屋旁的武器**　开局有一把日本刀、一把带瞄准镜的栓动步枪和一把手枪。任意队友看向地面武器按 **E** 拾取。按 **Tab** 可装备或丢下，也可按 **6**、**7**、**8** 切换已经拾取的武器。左键挥刀或射击，按住右键用步枪瞄准镜或手枪机械瞄具。详见[营地开局武器](wild-people.md#营地开局武器)。
- **房间与重玩**　每间房最多 4 人，也可单人完成。首次打开默认进 `pine`。点网页的「另开营地」得到独立新房间，再将邀请链接发给队友。浏览器刷新会重连；关闭标签页再开可能获得新玩家身份，房间物资与修复进度按房间码保存。
- **Mac 与网页一起玩**　服务启动后运行 `npm run coop:native`，即可从 LaunchServices 打开同一个默认房间的 Mac 发行版。也支持 `npm run coop:native -- '完整网页邀请链接'`。房主的 Mac 自动从回环地址连接自己的服务，复制给朋友的邀请仍指向同网地址。两端共享 GDScript 移动、碰撞和交互规则。
- **仅在自己电脑上玩**　可用 `npm run coop` 启动回环服务。两台设备组队要使用 `coop:lan`。若已经在前台启动了仅本机服务，先在它的终端按 Ctrl+C，再用局域网命令启动。

本轮修复的试玩服务已按用户要求关闭；可用下方命令重新启动同一存档，入口为 [本机营地](http://localhost:4284/coop/?room=pine)。原房间与当前标签页身份会继续，服务使用独立发行目录与原存档。新窗口先读[简短交接](next-session.md)：

```sh
COOP_SITE_DIR=dist/coop-resource-fix COOP_PORT=4284 COOP_ROOM_PORT=4285 COOP_SAVE_DIR=.local-rooms/wild-people npm run coop
```

已有 4184 服务与其存档不需停止。4284 已运行时不要重复启动。更新/备份和本轮验证见[背包资源修复记录](coop.md#个人物资与溪水)。

## 合作版实现与复验

营地到溪谷的小径旁有八株会长大的树：四株松树、两株白桦、两株云杉。在木棚外朝左看，可以先找到白色树干的成桦。新开营地能看到从幼苗、幼树到成树的过程。走近并看向其中一株，可读到阶段提示。房间无人时成长暂停，再进房会延续此前的树龄。


原林地的细节分为 7 个分块，共用 PBR 纹理。先请求营地几何，再按距离预取相邻区域，走远后释放旧分块。海岸随游戏包首开驻留，和溪谷、湖岸、瞭望塔及木棚处于同一块连续世界中。浏览器通过同源 WebSocket 与 Godot 权威服务器通信，Mac 使用相同协议。服务端校验距离、速度、材料与房间人数。任务和石块操作成功前原子保存，位置和天气约每 4 秒以及离房时保存。空房暂停时钟。存档位于项目的 `.local-rooms/`。

服务端使用已安装的标准版 Godot 4.7.2，无需导出模板即可启动。用 `npm run coop:build:web` 从源构建网页，需 Node.js、Python 3、NumPy、Pillow 和同版 Godot。Mac 上的 `npm run coop:build` 会同时构建网页和 Mac 客户端。网页使用 WebGL 2、Compatibility 渲染器与单线程导出，分块、WASM 和 PCK 均可用 gzip 传输。对外可访问的公网房间、Steam 好友邀请和手机触控尚未实现。

- [合作样片验证记录](coop.md)　·　[素材来源与许可](woodland-assets.md)。新地图沿用该页的 CC0 林地材质，新增木塔、溪流、物资和营地构件为本项目程序化几何。HUD 字体的来源及许可在 [NOTICE](../coop/fonts/NOTICE.txt)。
- 房间逻辑与断线复验可运行 `npm run coop:test`。服务启动后，用 `node scripts/coop-playtest.mjs` 复验网页与 Mac 的任务流程，用 `node scripts/coop-web-check.mjs` 复验浏览器限速首开和双浏览器入房，用 `node scripts/coop-flight-playtest.mjs` 复验飞行与停泊。自动化使用独立房间、无窗口浏览器和页面内输入。跨端试玩用 `--headless` 启动 Mac 发行版的可执行文件。
- 来袭者完整生命周期和真实模型/动作/面板复验运行 `npm run coop:test:wild -- evidence/wild-people-lifecycle.json`。浏览器加速验收可生成独立存档夹具：`npm run coop:fixture:wild -- .cache/wild-ui-rooms captive`；场景及独立端口启动方法见[专题验证入口](wild-people.md#实现与验证入口)。

### GitHub Actions

推送到 `main` 或打开 PR 时，Ubuntu 运行器用 Godot 4.7.2 执行无窗口测试，覆盖联机房间、重连、存档、生存状态、石块提示、点灯和日出。运行记录可在 [Co-op CI](https://github.com/skysf/cooper-game/actions/workflows/coop.yml) 查看。

在该页点 **Run workflow**，选择 `web` 或 `macos` 手动打包。成功后可下载对应的 Artifacts。将 Web 包中的 `index.html`、WASM、PCK、脚本和 `zones/` 放进 `dist/coop/`，即可启动本机房间服务。Mac 客户端加入同一服务加载分块。

独立的画面回归工作流会构建参考与候选版本，在同一浏览器内比较固定机位截图。有显示器的 Apple M1 可另外验收 30 FPS、帧时和首次点灯、日出、飞船转向时的停顿。测试命令、阈值和差分图的读法见[画面与帧时基准](render-benchmark.md)。

## 原始 A/B 对照片

在当前项目目录运行以下命令。两份网页发行构建已放在 `dist/`，本机试玩只需 Node，无需打开编辑器。服务仅监听本机回环地址。

```sh
npm start
```

| | 自由试玩 | 固定路线测试 | 大雨迭代 |
|---|---|---|---|
| A · Babylon.js + TypeScript | [进入林地](http://localhost:4173/a/) | [测试 60 秒](http://localhost:4173/a/?bench=1) | [大雨试玩](http://localhost:4173/a/?profile=storm) |
| B · Godot 4 + GDScript | [进入林地](http://localhost:4173/b/) | [测试 60 秒](http://localhost:4173/b/?bench=1) | [大雨试玩](http://localhost:4173/b/?profile=storm) |

点击「进入林地」，用 **WASD** 行走、鼠标看向四周。沿泥路走约 98 米到木棚。行走模式累计 30 秒开始下雨，**R** 可手动切换，**Esc** 暂停并释放鼠标。沿原路或在棚内都可继续活动。固定路线会自动行走，30 秒切换天气，60 秒后显示成绩，可下载逐帧 JSON。

**复核画面**　在任一版地址后加 `?view=clear` 或 `?view=rain` 即可停在同一个机位。`?view=rain&profile=storm` 使用加大的雨量和更湿的泥地。同一时刻只打开一个活动的 3D 页面。

## 运行与重建

- 运行已有 Mac 版可用 `open dist/native/Woodland.app`。原生走 GDScript 输入与碰撞。用 Finder 双击也会通过 macOS 的 LaunchServices 启动。
- 安装开发依赖用 `npm ci`。更新 A 用 `npm run build:a`，更新 B 用 `npm run build:b`。从源码重新打包 Mac 用 `node scripts/godot.mjs build-native`。两端的场景生成和导出均在命令行完成。
- Godot 脚本查找 `/Applications/Godot.app`、`~/Downloads/Godot.app` 与 PATH，也支持 `GODOT_BIN` 指定可执行文件。此项目锁定标准版 4.7.2，Web 用单线程 release 模板和 Compatibility 渲染器。重新取得缺失模板时，脚本会从官方归档提取所需条目，在项目缓存中校验。 [Godot 4.7.2](https://godotengine.org/download/archive/4.7.2-stable/) · [Web 导出说明](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)
- 再测浏览器请先启动服务。在另一终端运行 `npm run benchmark`，复用同一个无窗口浏览器页面运行 A 冷、A 热、B 冷、B 热。用 `npm run benchmark -- qa` 复核控制与截图。输出默认写入 `evidence/`，可用 `WOOD_TEST_OUT` 指定独立目录。

## 场景和基准

[layout.json](../shared/layout.json) 定义路线关键帧、水平视野、相机裁剪面、玩家尺寸、晴雨参数与两个天气档位。生成的 [scene.json](../shared/scene.json) 固定实际物体位置、尺寸和碰撞范围。[同一份 GLB](../shared/woodland.glb) 内嵌五套 CC0 PBR 材质，来源和逐文件校验见 [素材说明](woodland-assets.md)。

两份 Web 样片使用同一浏览器控制器处理鼠标、键盘、平地约束、水平圆形碰撞、路线与测量。A 的世界由 Babylon 渲染；B 的场景加载、相机、材质、照明、雨丝和原生模式由 GDScript 实现。这样可比较网页交付和渲染成本，尚不能据此估算完整生存玩法的物理或脚本开销。

两边都要求 WebGL 2，绘图缓冲区固定为 1280 × 720。每次首帧后检查 `drawingBufferWidth/Height`，尺寸不符会中止测试。水平 FOV 78°，绘制远面 115 米，雾参数、雨丝几何与数量见共享清单。两边均关闭 MSAA 和几何 LOD。无窗口结果用于本机画面和行为复验。

平均 FPS 用帧间隔个数除以该阶段所有间隔之和（秒），P95 取排序后的第 ⌈0.95N⌉ 个间隔。按上一帧所属天气统计跨界间隔，雨天统计包括一秒的天气过渡。首次可操作为页面导航开始到首次场景完成渲染且输入按钮已启用。数据包括网页解析、下载、WASM 或 JS 初始化和首帧准备，属于应用帧间隔，尚未测 GPU 单帧耗时。
