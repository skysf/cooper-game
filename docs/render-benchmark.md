# Cooper 画面与帧时基准

网页版的体验底线是稳定 30 FPS。一个画面需要在约 33.3 毫秒内显示出来。营地、湖面和飞船驾驶分别验收，一处场景的高帧率不能抵消另一处的停顿。

## 测什么

| 场景 | 要看清的画面 | 要捕捉的停顿 |
|---|---|---|
| 晴天林地 | 近树树皮、针叶轮廓、林下阴影和远树层次 | 移动与分块加载 |
| 湖岸 | 近岸浅水、远岸倒影和波纹，雨天能看出水面变化 | 转向水面、倒影刷新 |
| 水下 | 向上可见水面，近处湖床与远处水体有明暗、色彩层次 | 镜头穿过水面和首次显示湖底 |
| 木屋点灯和日出 | 灯前后的亮度变化、晨光、天空和地表色调衔接 | 效果首次出现的那一帧，以及随后的数帧 |
| 飞船 | 驾驶员坐姿、前进时船尾双喷口、垂直起降时船腹喷口，斜向爬升时两组同时出现 | 第一和第三人称连续转弯时的机体与相机运动 |
| 背包与服装 | 选中态、物品详情、角色和操作按钮清楚可见 | 首次打开和切换页面 |

## 如何判读

记录逐帧时间、实际绘制帧数、平均 FPS、P95 帧时、超过 50 毫秒的帧和最长连续慢帧。P95 是从快到慢排列后第 95 百分位的帧间隔。首次点灯、打开装备和进入新分块要保留首次触发的数据；平稳行走则另列预热后的采样。飞船即使按时出帧，机体仍可能被网络快照拉回，所以驾驶回归还要检查转向是否出现回跳。

截图比较要固定存档、玩家位置、朝向、镜头、时刻、天气、渲染分辨率和浏览器版本。湖岸和点灯各保留局部对照；小物体消失很容易被大面积相同的背景掩盖。对比失败时一起保留参考图、实测图和标记差异的图片。刻意修改美术时由人查看差异并更新参考图，CI 只读参考图。[Playwright 画面对照说明](https://playwright.dev/docs/test-snapshots)

性能样本记录 GPU、浏览器、绘图缓冲区和页面可见性。固定硬件任务使用有硬件加速的前台浏览器，同一台机器串行采样。普通 CI 的功能、画面和资源检查可在独立运行器执行。浏览器切到后台会改变动画帧调度，该段样本应标记为无效。[浏览器动画帧调度](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) · [GitHub Actions 定向选择运行器](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/use-in-a-workflow)

正式前台采样前先在同一窗口测空白页。此前 Apple M1 的外接 LG 4K 运行在 25 Hz 时，空白页为 25.00 FPS，P95 为 40.7 毫秒，林地、湖面和日出也都接近 25 FPS。专用运行器需要足够刷新率的显示器，并在空白页确认可用的刷新上限。

### 第一次飞船起飞和转向

从营地起飞后首次转到木屋门廊，浏览器可能在同一小段转向里首次链接油灯玻璃、自发光材质和阴影深度的着色程序。网页版在进入林地前用 96 × 54 的临时视口绘制一次实际油灯。预热沿用场景的世界、灯光与阴影，视口退出后开放输入。

Apple M1 上用 Chrome 157、Metal、1280 × 720 串行对照同一份素材。程序源散列确认 24 次链接全部提前到开放输入前，整轮链接总数仍为 208。

| 锁屏诊断 | 预热前 | 预热后 |
|---|---:|---:|
| 首次追机转向实际提交 FPS | 56.38 | 60.00 |
| 首次转向最大帧时 | 216.7 ms | 16.8 ms |
| 首次转向超过 50 ms 的帧 | 3 | 0 |
| 首次转向内链接的程序 | 24 | 0 |
| 导航到首次可操作 | 6.49 s | 6.72 s |

这轮临时视口从建立到退出用时 1.37 秒，包含启动时的首帧。首个可操作时刻实测推迟约 0.23 秒。关闭追踪后复验，首次转向最大帧时从 233.4 毫秒降至 16.8 毫秒，首个可操作时刻相差约 0.01 秒。[逐帧与着色程序记录](../evidence/flight-lantern-warmup.json)

解锁后在 M1 内建屏上复验，起飞时还有一组来自喷焰材质的首次链接。同一个临时视口现在也绘制两组喷口共用的材质。前台配对追踪中，起飞内链接从 5 次减到 1 次，最大帧时从 100.0 毫秒降到 17.7 毫秒。剩余的无局部点光源变体链接查询耗时约 2.3 毫秒。完整前台飞行关闭追踪，起飞、追机和座舱转向均为约 60 FPS，最大帧时依次为 17.8、17.7 和 17.7 毫秒，三段均通过硬件门禁。[前台逐帧与门禁记录](../evidence/flight-foreground-warmup.json)

飞行脚本在报告中保存首次可操作用时和临时视口从建立到释放的用时。设置 `COOP_FLIGHT_TRACE=1` 可额外保存 Chrome GPU 时间线。Mac 自动试玩默认用无窗口 Chrome 和 ANGLE Metal，适用于锁屏时的诊断。正式帧时通过专用运行器采集。

## 本地复验

先保存准备对照的网页版发行目录，包含 `index.pck`、`index.wasm` 和 `zones/`。然后构建候选版本。以下命令在无窗口浏览器中比较两个版本，鼠标锁定和焦点由测试页模拟，键盘操作仍经过游戏的输入处理。Mac 默认用 ANGLE Metal，报告保留实际 GPU 和提交帧间隔。

```sh
npm run coop:build:web
npm run coop:render:test
COOP_BENCH_SCENES=forest,lake,lamp,dawn,storm \
npm run coop:render:benchmark -- /path/to/reference/coop dist/coop
npm run coop:render:score -- .cache/coop-render-benchmark/render-benchmark.json \
  --scenes forest,lake,lamp,dawn,storm
```

硬件判定采用游戏实际向主画布提交绘制的帧间隔。每个场景需达到平均 30 FPS、P95 不超过 34 毫秒。超过 50 毫秒的帧最多占 1%，连续两帧超过 50 毫秒或任一帧超过 100 毫秒均失败。评分退出码 0 表示通过，1 表示有回归或缺少必要证据，2 表示运行环境无效。原始逐帧数据、截图和差分图与评分 JSON 放在同一个输出目录。

## 角色预览首开

网页启动条从资源下载开始，继续显示光照、场景、角色预览和营地人物的准备情况。房间连通、出生位置林区载入且预热完成时，进度到达 100% 并显示可用的「进入林地」。延迟首个林区请求可复验加载条一直停在完成之前。 [加载与快捷键回归](../scripts/test-coop-startup-controls-web.mjs)

锁屏时，在 Apple M1 的无窗口 Chrome 157 上用 ANGLE Metal 交错运行修前包、最终包和重复基线。三组使用同一世界、角色模型与贴图，绘图缓冲区均为 1280 × 720。实际点击角色页后，WebGL 编译和链接调用从 45 次降到 0 次，点击到游戏上报页签状态从 270.3 毫秒降到 27.2 毫秒，动作窗口的最大提交间隔从 250.0 毫秒降到 16.7 毫秒。[逐帧数据](../evidence/camp-ui/preview-warmup/before.json) · [最终包](../evidence/camp-ui/preview-warmup/after.json) · [重复基线](../evidence/camp-ui/preview-warmup/before-repeat.json)

最终包的背包、角色页和暴雨在六秒样本中均约 60 FPS，最大提交间隔 16.8 毫秒。角色首绘在油灯预热后的加载遮罩内耗时 252–302 毫秒。本轮从导航到可操作为 6.02–6.95 秒，进入可操作后的首 500 毫秒间隔最大 16.8 毫秒。初轮中系统编译和索引同时占用 CPU，Tab 确认后及静止暴雨也出现慢帧。该轮和交错复测的数值一并保留。 [诊断汇总](../evidence/camp-ui/preview-warmup/summary.json)

首绘纹理保留全身高度和原有光照。对照图中的角色轮廓高度一致，随后用 1600 × 900 和 960 × 540 的浏览器窗口复核显示和拖转。 [修前角色页](../evidence/camp-ui/preview-warmup/equipment-before.png) · [修后角色页](../evidence/camp-ui/preview-warmup/equipment-after.png) · [大窗口](../evidence/camp-ui/preview-warmup/equipment-1600x900.png) · [紧凑窗口](../evidence/camp-ui/character-compact-web.png)

## CI

推送到主分支或创建 PR 时，工作流分别构建参考提交和候选提交，在同一版 Chromium 与 SwiftShader 中比较画面。可将已认可的美术版本的完整提交 SHA 填入仓库变量 `COOP_APPROVED_RENDER_SHA`，后续多个小改动都与同一版比较。未配置变量时采用 PR 基底或本次推送前的提交。手动运行时的 `reference_sha` 优先级最高。刻意改美术时先审阅目标机位及差分图，再更新变量。[CI 工作流](../.github/workflows/coop-render.yml)

本机 SwiftShader 复验中，湖岸水面与三栏背包的有意改版触发了画质复核，油灯点亮通过比较。[评分](../evidence/render-ci/render-score.json) · [湖岸差分](../evidence/render-ci/diff-lake.png) · [背包差分](../evidence/render-ci/diff-inventory.png)

SwiftShader 的画面检查使用真实房间消息，按固定模拟时刻截取两个版本的湖岸、修屋点灯前后、背包和角色页。浏览器仍用实际经过的时间记录帧间隔。画面比较会分别检查物品大图、人物和装备等局部。若参考版缺少可识别的角色页控件，报告会注明这一项只验证候选版能切页且人物可见。固定硬件检查另行衡量 30 FPS。

软件渲染测试先让每个发行包用自己的下载器读取地形分块，再启动着色器预热。加载页显示期间主画布使用 320 × 180。房间就绪后恢复并核实 1280 × 720，再记录截图和帧间隔。分块下载失败、浏览器错误和图像差分均会导致检查失败。

固定 Apple M1 的帧时检查通过主分支手动触发。工作流在带 `self-hosted`、`macOS`、`ARM64`、`cooper-render-gpu` 标签的专用运行器上显式启用 `COOP_HARDWARE_FOREGROUND=1`，需要已解锁的桌面和前台显示会话。无窗口报告提交给硬件评分时，结论为环境无效。锁屏、性能追踪和改动飞行路线也会使硬件样本失效。每次运行保留参考画面、候选画面、差分图和逐帧数据。
