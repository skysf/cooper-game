# 绑定和引擎验收

## 绑定与形态

- 坐标轴调整后验证实测包围盒和朝向。导入模型可能处于四元数模式，直接改欧拉值可能不会生效。应用与 Blender 模式一致的变换。GLB 导出后再次确认朝向和接触平面。
- 地上行走的动物需要四足分别控制。先按实际关节和脚掌定位，再用顶点权重把各腿与胸腹连接。检查权重归一化，尤其是脚趾和身体相邻处的误绑定。网页资产可以把每个顶点限制在最多四个非零骨骼权重，以保留较简单的蒙皮。
- 形态键要从同一 Basis 初始化，分别检查每个键只改动预期区域。检查独立的肩带和腰带时尤其注意旧键累计到新键。骨骼与折翼形态键联动时，确保从收翼动作切到展开动作，权重在引擎中也能复位。
- 逐帧查看脚底、尾尖、嘴角、飞羽和趾爪等关键部位。四足行走或跛行时看支撑脚接触和身体重心。游泳时看摆尾传递、收腿和水位。大幅张口时从侧面和正前斜上方看下颌实际开度、牙齿位置和邻近前肢变形。栖枝以明确的枝径和对齐轴做实物接触预览。验证最终交付用的权重与接触点。

## 动作和 GLB

- 如果游戏控制实际位移，行走、跑步和主要飞行做成原地动作。记录动作中的局部位移和游戏节点的位移。下潜、上浮可以用骨骼表现上下姿态，实际水位由场景管理。把循环动作的首尾对齐，单次动作的收势与下一状态对齐。
- 在 Blender 把动作按用途命名，保留用户需编辑的 Action 和 NLA 轨道。需要把骨骼和形态键烘成同一动作时，可以给两者的 NLA 轨道使用相同导出名称，用 NLA Tracks 模式导出，并确认最终 GLB 每个相关动作都有 `weights` 通道。不同 Blender 版本要确认选项和行为。
- 在 Godot 可用 `-loop` 或 `-cycle` 的导入约定，但导入显示名称可能去掉后缀。用实际 `AnimationPlayer` 读取名称、长度和循环模式。逐个播放并采样骨骼姿态。对折翼等形态切换，用同一个实例从折叠动作切到飞行，随后再切回，读取形态键的实际权重。
- 导出后核对可见网格和材质数、总三角面、内嵌贴图、蒙皮和必要的对齐标记。临时灯光、采样枝条、检查用几何和高模留在工作场景或验收素材中。纯资产请求可用隔离的引擎项目验证。
- 如果任务要求实际性能验收，用目标设备、相同相机、分辨率和对象数量对比关键场景。记录每种条件下的下载体积、帧耗时和镜头。用真实帧耗决定是否加 LOD 或重调纹理、材质和实例预算。

## 人形动作与实际视角

- 玩家说看不到腿脚时，分别查看源网格、装备切换和游戏相机。可用同一副身体在第一人称收起头、眼镜和帽子，按向下看的角度调整身体与镜头间距，再在游戏内看膝盖、鞋面及走路时的落脚。
- 按骨架实际朝向摆出预备、接触、随动和收回姿势。侧面看肩、肘、手腕的前伸距离，正面看重心和另一只手，近景看拇指是否回到掌侧。固定脚掌的动作可用腿部 IK 定住双踝，移动中可让下半身继续采样当前步态。
- 在常穿衣物、盾牌及裸臂下分别采样。袖口与手腕的距离要按实际蒙皮顶点测量。远离袖口的小片布若随手移动，回查它在静止网格中的位置和所属连通分量。皮肤顶点色与底色贴图混合时，复查引擎材质是否启用了顶点色。
- 联机动作可从房间认可的动作及时间取样。同一次输入要在本人、队友和切换视角后看到同一侧手；检查连续输入、动作中断和恢复步态时的姿势。
