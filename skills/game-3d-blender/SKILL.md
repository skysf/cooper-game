# Game 3D Blender

先确定用户要检查、修改 Blender 源文件、导出游戏资产，还是接入游戏。按这个范围交付。已有生成模型时先评估它是否能修复。单次生成的面数、贴图档位和模型品牌只能作为素材来源信息。

## 工作流程

1. **检查原件。** 对照参考图，从正面、侧面、背面、俯视和必要的底面查看。检查缩放、朝向、原点、材质、透明模式和现有绑定。开口、薄片、接触部位及重复肢体要看真实网格。亮度可疑时分别查看基础色预览和 PBR 渲染。用 [inspect_glb.py](scripts/inspect_glb.py) 读取 GLB 面数、贴图、蒙皮和动画清单。记录原件路径和基准，另存新文件。
2. **按用途修形。** 硬质道具优先保外轮廓和挂载点。服装优先保衣口、薄布和贴身形态。角色与动物优先保运动关节、接触面及外观特征。减面后把全貌、接缝和缺陷区放回相同视角比较。具体方法见 [模型修复](references/model-repair.md)。
3. **按请求制作绑定和动作。** 为需要独立运动的部位建立骨骼或形态键。选一个一致的米制参考尺寸，标明朝向和接触点。按动作可读性、脚或爪的接触、变形质量来调绑定。处理循环、单次、原地运动和实际位移时见 [绑定和引擎验收](references/rigging-and-export.md)。
4. **验证交付件。** 从磁盘复开最终 `.blend`，检查贴图打包、网格、形态键和动作。导出 GLB 时只选择交付所需内容。用引擎导入最终文件，播放实际动作并检查动作切换和循环。记录实测的尺寸、面数、材质、大小及剩余限制。独立引擎导入能验证资源和动作，场景性能要在目标设备和实际场景测。

## 工作环境

- 现场已有 Blender 工作窗口时，优先在独立后台 Blender 或 Blender MCP CLI 会话中处理副本。用 `bpy.app.background` 和当前打开路径确认工作上下文。把耗时减面、动作导出和渲染分开，保留可复查的中间结果和日志。
- 本项目用 `./scripts/start-blender.sh --background` 启动后台 Blender。若 macOS Metal 预检失败，用原参数在能访问 Metal 的会话中重试。Codex 中为本次 Blender 启动请求 `require_escalated`。[启动与排查](../../docs/blender-mcp.md#后台启动与-metal)
- 以现有项目的单位、坐标、资源目录和导入约定为准。若用户要求只改 Blender，就按这个范围保存。输入规模决定面数和贴图预算，近景、变形和实例数决定最终取舍。
- GLB 检查可在技能目录运行 `python3 scripts/inspect_glb.py /path/to/asset.glb`，也可一次传入多个路径。安装了 Pillow 时会附加内嵌贴图尺寸。
